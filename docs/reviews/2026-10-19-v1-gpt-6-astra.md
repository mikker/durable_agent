# Independent review by GPT-6 Astra through Codex (2026-10-19, HEAD e0d356e, one-database design)

Read-only. Codex's sandbox denied file writes and local database access, so the Rails suites and the file-backed sidecar suites did not run; targeted checks over in-memory SQLite did (config and translator tests 7 pass; pi-durable's 24 conformance cases pass both plain and through the base-document wrapper and change tracker); `tsc --noEmit` passed.

## 1. Confirmed findings

**P1 — Resuming before tools load permanently fails recoverable tool calls.** `sidecar/src/main.ts:55`, `sidecar/src/harness.ts:77`. The sidecar stops while a Rails tool marked `replay: safe` is running. On restart `harness.resume()` runs before the asynchronous tool-definition fetch finishes. pi-durable's recovery needs both the persisted policy and the currently resolved tool to say `safe`; with an empty registry it settles the call as interrupted, and loading the tools afterwards does not revive it. Reproduced with the real Harness over retained `MemoryStorage`: the persisted `pi.tool-result` contained "Tool lookup was interrupted and may have partially run" and the submission settled `done`. Resumable work is lost; no stored rows are corrupted. Fix: gate recovery and new model runs on tool readiness.

**P2 — Postgres retries writes that may already have committed.** `sidecar/src/db/postgres.ts:160`, `sidecar/src/reports.ts:30`. An autocommit statement commits but its response is lost with `ECONNRESET`, and the adapter repeats it. Repeating `INSERT … RETURNING id` creates two reports and only the second id reaches `events.report`. A fault-injection pool made the real `PostgresDatabase` run the statement twice and return id 2. Explicit-transaction commits are not retried. Fix: restrict retries to operations known to be safe.

**P2 — Rails scopes do not match pi-durable's string encoding.** `app/models/durable_agent/submission.rb:16`, `document.rb:15`, `task.rb:9`. A request id like `a&b` is stored by pi-durable as `"a&b"`, but Rails' `to_json` writes `"a&b"`, so `Submission.for_request("a&b")` finds nothing; the same applies to custom kinds with HTML-sensitive characters. Verified against the real Submission model on in-memory SQLite: 0 matches. Fix: a shared indexed-string encoder compatible with `JSON.stringify`, tested against values the sidecar wrote.

## 2. Plausible, not reproduced

- **SQLite writer contention.** `conversation.rb:60` waits synchronously for a sidecar commit. If Rails already holds a write transaction, the sidecar's `BEGIN IMMEDIATE` waits for the same lock; the five-second timeout then becomes a session-fatal storage failure.
- **Shutdown.** `main.ts:79` calls `server.close()` without awaiting it before closing the Harness, so in-flight requests may be cut off.
- **Postgres config handoff.** `sidecar.rb:57` does not pass `schema_search_path` or certificate paths.
- **Long indexed strings.** Large request ids or document keys may exceed Postgres B-tree entry limits and become fatal storage errors.

## 3. Contract disagreements

- The specified resume-before-load boot order undermines the recovery promise; the contract needs changing as well as the code.
- `storage.ts:24` turns only the conversations-table check into `MissingSchema`; a missing `durable_agent_durable_metadata` gives a plain "no such table".
- Rails ignores `DURABLE_AGENT_WORKSPACE_ROOT` and `DURABLE_AGENT_NAME` (`configuration.rb:15`) and the launcher overwrites them.
- `config.ts:35` accepts a whitespace-only token while Rails rejects it.
- `application_controller.rb:8` uses `delete_prefix`, so a bare secret without the Bearer scheme also authenticates.

## 4. Test quality

Reasonably supported: rollback, global ids, document lifecycle and pagination (conformance suite); the Postgres serial queue holds a whole transaction callback; the wrapper serializes read-rewrite-commit; no extra Postgres translation defect found by inspecting the installed core and migrations; credentials use random GCM IVs and per-provider serialization.

Overstated: recovery is never tested (the test helper awaits tool loading, production serves while loading continues); retry tests inject failure before execution, so they cannot catch a statement that already committed; WAL is checked only as a pragma, with no contention test; the schema test compares names only; streaming equality is checked only after settlement; fixtures encode indexed strings with Ruby, hiding the encoding finding; the round-trip test disables Rails callbacks; shutdown, pending HTTP bodies, OAuth persistence and real Postgres disconnects are untested.

## 5. First three changes

1. Make tool readiness part of recovery admission, with a restart test using a persisted safe tool call and delayed Rails availability.
2. Remove ambiguous write retries, and test failure after a simulated commit.
3. Unify indexed-string encoding across Ruby and JavaScript, with cross-language tests.

## 6. Prerelease verdict

Not ready to advertise reliable crash recovery, because the tool-registration race breaks that promise. The SQLite storage design held up under the tests that ran, and no base-document corruption was confirmed. A file-backed Puma contention test and a full run of both suites outside the sandbox are still needed.
