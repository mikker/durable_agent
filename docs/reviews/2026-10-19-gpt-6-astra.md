4. **Medium — A failed final frame never retries while the conversation is idle.**  
   [mirror.ts:215](/Users/mikker/dev/durable_agent/sidecar/src/mirror.ts:215)  
   Clearing bookkeeping only helps when another frame arrives. If Postgres rejects the final answer or idle-state frame, the conversation has no reason to emit another one. Rails can indefinitely lack the answer or report `busy? == true` after Postgres recovers. Restarting repairs frames, but normal operation does not. Recovery needs scheduled retries independent of agent activity.

6. **Medium — Database disconnects terminate both background processes without recovery.**  
   [main.ts:22](/Users/mikker/dev/durable_agent/sidecar/src/main.ts:22), [relay.rb:15](/Users/mikker/dev/durable_agent/lib/durable_agent/relay.rb:15)  
   The Postgres pool has no `error` listener; an idle connection failure emits an unhandled error. The relay rescues errors inside notification dispatch, but connection failures from `wait_for_notify` occur outside that rescue. A database restart or failover therefore kills the sidecar and relay. Without an external restart policy, agent execution and broadcasts remain unavailable; there is no reconnect/re-LISTEN loop.

7. **Medium — OAuth tokens are stored as plaintext application data.**  
   [credentials.ts:60](/Users/mikker/dev/durable_agent/sidecar/src/credentials.ts:60)  
   Access and refresh tokens are serialized directly into JSONB using the application’s database connection.
